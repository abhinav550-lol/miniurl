
# User Stories – URL Redirection Service

## Epic: URL Resolution

### US-RED-001: Redirect Using Short URL

**As a** visitor
**I want** to access a shortened URL
**So that** I am automatically redirected to the original destination.

**Acceptance Criteria**

* Given a valid short URL
* When I visit the URL
* Then I receive an HTTP redirect (301/302)
* And I am taken to the original URL within an acceptable response time.

---

### US-RED-002: Resolve URL from Cache

**As a** system
**I want** to retrieve URL mappings from Memcached before querying the database
**So that** redirection latency is minimized.

**Acceptance Criteria**

* Service checks Memcached first.
* If mapping exists, PostgreSQL is not queried.
* Redirect is performed immediately.
* Cache hit is logged for monitoring.

---

### US-RED-003: Populate Cache on Cache Miss

**As a** system
**I want** to cache URL mappings after retrieving them from PostgreSQL
**So that** future requests are served faster.

**Acceptance Criteria**

* Cache miss triggers PostgreSQL lookup.
* Retrieved mapping is stored in Memcached.
* Redirect proceeds successfully.
* Subsequent requests are served from cache.

---

### US-RED-004: Handle Invalid Short URLs

**As a** visitor
**I want** to see an informative error page when a short URL doesn't exist
**So that** I understand the link is invalid.

**Acceptance Criteria**

* Unknown short code returns HTTP 404.
* User-friendly error page is displayed.
* No redirect occurs.

---

### US-RED-005: Handle Expired URLs

**As a** visitor
**I want** expired links to display an expiration message
**So that** I know the link is no longer available.

**Acceptance Criteria**

* Expiration timestamp is validated.
* Expired links return an appropriate error response.
* No redirect occurs.

---

## Epic: Redirect Behavior

### US-RED-006: Support Permanent Redirects

**As a** URL owner
**I want** permanent redirects to return HTTP 301
**So that** browsers and search engines treat the destination as permanent.

**Acceptance Criteria**

* Redirect type is configured as permanent.
* Service returns HTTP 301.

---

### US-RED-007: Support Temporary Redirects

**As a** URL owner
**I want** temporary redirects to return HTTP 302
**So that** browsers do not permanently cache the redirect.

**Acceptance Criteria**

* Redirect type is configured as temporary.
* Service returns HTTP 302.

---

## Epic: Performance

### US-RED-008: Serve High-Traffic Requests Efficiently

**As a** system administrator
**I want** URL redirection to scale under heavy traffic
**So that** users experience minimal latency.

**Acceptance Criteria**

* Cache serves frequently accessed URLs.
* Database load is minimized.
* Response time remains within target SLA.

---

## Epic: Click Tracking (V2)

### US-RED-009: Record Click Event

**As a** URL owner
**I want** every successful redirect to be recorded
**So that** I can analyze link usage.

**Acceptance Criteria**

* Every successful redirect generates a click event.
* Event includes:

  * Short URL ID
  * Timestamp
  * Click count increment
* Recording does not noticeably delay redirection.

---

### US-RED-010: Maintain Click Count

**As a** URL owner
**I want** my link's total click count to be updated automatically
**So that** I can measure popularity.

**Acceptance Criteria**

* Click count increments after each successful redirect.
* Failed redirects do not increment the count.

---

### US-RED-011: Store Monthly Analytics

**As a** URL owner
**I want** clicks to be grouped by month
**So that** I can view monthly traffic trends.

**Acceptance Criteria**

* Click events are aggregated by month.
* Monthly totals are available for visualization.

---

### US-RED-012: Store Yearly Analytics

**As a** URL owner
**I want** yearly click statistics
**So that** I can analyze long-term usage.

**Acceptance Criteria**

* Click events are aggregated by year.
* Historical yearly totals are maintained.

---

### US-RED-013: Preserve Click Timestamp

**As a** URL owner
**I want** the timestamp of each click to be recorded
**So that** analytics can be generated accurately.

**Acceptance Criteria**

* Each click event stores its timestamp.
* Timestamps are recorded in UTC.
* Data can be aggregated by day, month, and year.

---

## Epic: Reliability

### US-RED-014: Continue Redirecting During Cache Failures

**As a** visitor
**I want** URLs to continue working even if Memcached is unavailable
**So that** links remain accessible.

**Acceptance Criteria**

* Service falls back to PostgreSQL.
* Redirect still succeeds when the mapping exists.
* Cache errors do not affect end users.

---

### US-RED-015: Handle Database Misses Gracefully

**As a** visitor
**I want** nonexistent URLs to fail gracefully
**So that** I receive a clear response instead of a server error.

**Acceptance Criteria**

* Missing mappings return HTTP 404.
* Service remains stable.
* No unnecessary retries occur.
